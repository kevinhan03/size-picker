# 에이전트 운영

ops-v3는 후속 질문에서 변경한 필터·세션·개인화 맥락 필드를 구조화해 식별하고 서버에서 나머지 조건을 유지한다. 새 검색은 이전 필터를 병합하지 않는다. 명시적인 조건 해제는 null/빈 배열로 적용한다. 판단은 intent 모델에 의존하므로 실제 대화 검증이 필요하며, session_update 이벤트에서 이전/해석 후 조건을 확인할 수 있다. 세션 상태는 대화 안에서만 저장되고 장기 취향 데이터에 쓰지 않는다.

추천 카드의 evidence에는 근거 컬렉션, 분석 상품 수, 근거 신뢰도, 세션 적합도, 시각 분석의 한계를 담는다. 스타일 유사도는 구매 확률이 아니며 상품 자체 스타일 축 분석값을 변경하지 않는다. 예전 카드는 evidence 없이도 표시된다.

관리자 홈 → 에이전트 운영(`/admin/agent`). 기존 관리자 세션으로 접근한다. 세션이 없으면 관리자 홈에서 로그인한다.

요청 목록은 30건씩 조회하며 완료/실패/처리 중 및 미검수 필터를 제공한다. 상단 응답 시간과 완료 건수는 **현재 페이지** 기준이다. 처리 중이 오래 유지되면 서버 중단 등의 가능성이 있으므로 실행 상태를 별도로 확인한다.

기존 `fashion_agent_requests.response`로 과거 질문·답변·카드를 읽는다. 과거 실패 요청에는 질문 원문이 없을 수 있다. 추가 계측 적용 이후 승인된 요청부터 원문·언어·소요 시간·오류 코드·설정 모델명·실행 버전 및 구조화된 단계 진단을 저장한다. 요청 승인 전 인증/형식 오류/호출 한도 거절은 실행 로그 대상이 아니다. 캐시 재시도는 같은 요청을 중복 기록하지 않는다.

실행 진단은 질문 해석, 평균 취향, 카탈로그 검색 채널별 후보 수, 랭킹 상위 후보의 기준 점수/세션/새로움/피드백 점수다. 질문 기반 취향 관측이 활성화되면 그 진단도 같은 요청에 연결된다. 다단계 요청은 이벤트 순서로 구분한다. 숨은 추론은 저장하지 않는다. 실제 화면에 반환된 상품은 응답 카드가 기준이다.

`fashion-agent-ops-v2`부터 오케스트레이션·검색·취향·랭킹 버전을 각각 기록한다. 평균 취향의 신뢰도는 스타일 축이 있는 상품 수(12개에서 포화), 전체 저장 상품 중 분석 가능 비율, 축 일관성을 합산한 보수적 휴리스틱이다. 카테고리 범위는 진단값으로만 기록하며 특정 카테고리에 집중된 사용자를 감점하지 않는다. 신뢰도가 낮으면 장기 평균보다 이번 질문의 세션 스타일 방향이 상대적으로 더 크게 작동한다. 세션 방향이 없는 경우에는 기존 평균 취향 순서를 유지한다. 이 신뢰도는 사용자의 취향 품질을 평가하는 절대 점수가 아니라, 현재 개인화 근거의 양과 일관성을 나타낸다.

후보 흐름은 엔진에 들어온 후보군과 하드 필터 적용 후 후보 수, 랭킹 및 실제 노출 개수를 구분한다. 관리자 화면의 구조화된 요약은 신규 요청에서만 보이며 과거 요청은 원본 JSON 진단만 표시될 수 있다.

관리자 검수는 취향 적합성·설명 정확성·조건 준수 1~5점, 문제 단계, 메모로 저장한다. 공유 관리자 세션이므로 검수자 개인 신원은 기록하지 않으며 수정 시 기존 검수를 대체한다. 사용자 명시적 추천 피드백은 메시지와 대화 ID로 연결한다. 카드 클릭·저장 전환의 요청별 추적, 버전 간 자동 재실행 비교, 전체 기간 품질 집계는 아직 없다.

일반 사용자와 anon은 테이블에 접근하지 못하며 계정 삭제 시 기존 FK cascade가 유지된다. 관리자 API는 사용자 ID/이메일을 반환하지 않는다. 질문·응답·메모의 일반적인 이메일, 한국 휴대폰 번호, API 키 패턴은 표시 단계에서 마스킹한다. 이는 임의의 모든 민감정보를 판별하는 시스템은 아니다. 대화 원본은 기존 저장 방식으로 보존된다.

로그 계측 실패는 추천 응답을 실패시키지 않고 서버 경고를 남긴다. 애플리케이션 배포 이후 새 요청부터 실행 진단이 수집된다. 모델명은 설정값이며 응답 지연은 전체 요청 시간이다. 비용 또는 토큰 사용량으로 해석하지 않는다.
