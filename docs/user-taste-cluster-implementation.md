# 사용자별 취향 클러스터 v1

## 운영 경계

- 실제 추천 점수·순위·설명은 기존 엔진 그대로다. Dig Match 신호는 사용하지 않는다.
- `FASHION_AGENT_CLUSTER_SHADOW=true`인 서버에서만 추천 요청의 입력 관측과 비교 기록을 활성화한다. 기본값은 꺼짐.
- 추가 LLM 호출은 없다. 현재와 같은 최근 최대 500개 상품의 유효한 8축 분석을 사용한다.
- `digbox`와 `closet`을 분리한다. 최초 개인화 search/recommend 요청 시 해당 사용자·소스를 작업 목록에 등록한다. 전체 사용자를 자동 소급 등록하지 않는다.

## 계산과 보관

결정론적 farthest-pair 초기화 + k=2 means. 유효 상품 최소 8개, 그룹별 최소 3개, 최대 비중 85%, 중심 간 RMS 거리 최소 1 및 최대 그룹 평균 반경의 1.5배를 통과해야 한다. 임계값은 가설이며 실제 평가로 조정한다.

모델 JSON에 중심, 멤버 ID, 대표 상품 3개, 카테고리 분포, 반경, 축 기반 설명을 저장한다. 추측성 스타일 이름은 붙이지 않는다. 원천 분석 및 상품 목록의 fingerprint와 알고리즘 버전을 함께 보관한다. 탈락한 시도도 보관하고 이전 승인 모델을 삭제하지 않지만, 현재 fingerprint와 다른 모델은 비교에 사용하지 않는다.

저장/삭제 이벤트를 DB 트리거로 즉시 추적하는 방식은 아직 아니다. 추천 요청 및 일일 작업에서 변경을 관측한다. 관측 후 최소 6시간, 최근 처리 후 최소 24시간을 기다린다. 일일 작업이므로 실제 갱신은 변경 후 24~48시간 이상 걸릴 수 있다. 한 번에 최근 확인 시각이 오래된 100개 사용자·소스를 검사한다. 규모가 커지면 큐/분할 작업 및 이벤트 기반 무효화를 추가한다. 동일 fingerprint의 모델은 고유 제약으로 중복 저장되지 않는다.

## 비교 기록 해석

- 실제 순위 상위 5개(`baseline_ids`), 클러스터 취향 순위 상위 5개(`shadow_ids`).
- `plan.meanIds`: 같은 후보군에 평균 취향 유사도만 적용한 상위 5개. `plan.scores`: 후보별 평균/클러스터 점수.
- 질문의 축 선호가 있으면 그 축에 가장 가까운 클러스터, 없으면 상품별 가장 가까운 클러스터를 사용한다.
- `overlap`은 실제 순위 대비 겹침 비율일 뿐 성능/정확도 점수가 아니다. 검색 후보를 확장하지 않으므로 검색 재현율 향상도 증명하지 않는다.
- 현재 결과와 미노출 shadow 결과의 클릭률을 직접 비교하면 안 된다. 블라인드 평가를 먼저 진행한다.
- 모델 버전이 바뀌면 새 fingerprint로 재검증한다. 저장/삭제에 따른 클러스터 라벨 안정성은 보장하지 않으며 인덱스는 모델 내부에서만 유효하다.

## 실행·확인

1. 새 migration을 적용한 뒤 서버 환경에서 `FASHION_AGENT_CLUSTER_SHADOW=true` 설정.
2. 기존 CRON_SECRET 유지. 배포된 cron은 `/api/cron/taste-clusters`를 매일 03:47 UTC(12:47 KST)에 실행한다. 수동 호출도 Bearer CRON_SECRET 필수.
3. 개인화 추천 요청으로 사용자·소스 등록 → 안정화 시간 이후 worker 실행 → 다시 추천 요청하면 비교 기록 생성.
4. 로그인 상태에서 `/api/fashion-agent/taste-clusters?source=digbox`로 본인 모델 상태와 최근 비교를 확인한다. 타 사용자 ID 입력은 받지 않는다. UI 노출은 아직 없다.
5. `npx vitest run server/services/taste-clusters server/services/fashion-agent`, `npx tsc --noEmit`.

DB 테이블과 RPC는 service_role 전용이며 RLS 활성화. 실패한 shadow 기록은 실제 추천을 실패시키지 않는다. 다만 활성화 시 DB 왕복 시간이 추가된다. 운영 전 별도 부하/지연 검증 필요. 원시 질문은 저장하지 않지만 구조화된 plan과 상품 ID는 사용자 데이터이므로 보관 정책을 정해야 한다. 계정 삭제 시 cascade 삭제된다.

## 다음 평가

readiness 문서의 30문항과 대표 사용자 5명 이상으로 평균/클러스터 결과를 블라인드 비교한다. 취향 적합성과 설명 근거를 사람이 평가해야 하며 자동 overlap만으로 전환하지 않는다. 실제 추천 전환, 즉시 변경 트리거 및 대규모 큐는 아직 구현 범위에 포함하지 않는다.

## 사람 평가 화면

`/fashion-agent/evaluation`은 로그인한 사용자만 사용할 수 있는 50문항의 개인 평가 도구다. 각 문항은 LLM이 즉석에서 해석하지 않는 고정된 실행 계획을 사용한다. 따라서 이 단계는 검색·랭킹의 차이를 검증하며, 자연어 의도 해석 성능을 함께 측정하지 않는다. 각 문항마다 같은 엔진 후보군에서 현재 프로덕션 순위와 클러스터 순위를 만들고 A/B로 무작위 배치한다.

사용자는 두 결과의 취향 적합성, 설명 납득도, 조건 충족도를 1~5점으로 평가하고 A/B/동률 선호와 메모를 남긴다. 평가가 끝난 뒤에만 내부적으로 A/B를 평균 취향/클러스터에 다시 매핑하여 누적 평균과 선호율을 표시한다. 원본 질문, 후보와 점수, 평가는 서비스 역할만 읽고 쓰며 계정 삭제 시 함께 삭제된다.

50개는 단일 사용자 신호로는 충분하지 않다. 같은 방식으로 최소 5명의 클러스터 적격 사용자가 완료한 결과를 합산하고, 사전에 정한 전환 기준을 다시 확인해야 한다. 자연어 통합 평가는 이 고정 평가 통과 후 별도 세트로 진행한다.

## k=2 이후의 관측 모드

클러스터 평가 UI는 `FASHION_AGENT_EXPERIMENTS=true`에서만 접근 가능하며 일반 에이전트 화면에서는 숨긴다. `FASHION_AGENT_QUERY_TASTE_OBSERVATION=true`는 실제 추천을 바꾸지 않고, 방향성 요청에서만 저장 상품의 가능한 근거 집합과 관련도·분산·전체 평균과의 거리를 서버 전용 진단 테이블에 기록한다. 넓은 요청에는 근거 집합을 만들지 않는다. 이 단계의 50문항은 넓은 대조군 20개와 방향성 질문 30개로 구성되며, 임계값이나 랭킹 가중치를 확정하는 근거를 수집하기 위한 것이다.
